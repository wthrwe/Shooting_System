### 4.1 未修的风险

| # | 风险 | 影响 | 应对 |

| 1 | 🔴 **`osDelayUntil` 对过期时刻返回 `osErrorParameter` 且被 `(void)` 丢弃** | YOLO 推理一旦超 20 ms，视觉任务 100% 占 CPU ⇒ **把心跳饿死**，而心跳是**唯一诊断手段**。症状**不是"周期变长"，是"诊断先死"** | 这是 CMSIS 语义（`cmsis_os2.c:898`）**不是 bug**。应对：视觉任务里**测耗时并计数**，让它可观测，而不是等心跳消失 |

### 4.3 🔑 判据 / 观测方法论（反复吃过亏，已固化成习惯）

- **灯色 / 屏显也是"观测量"，同样要先追到赋值链**：第三十九次我把**驱动器蓝灯**当成"堵转保护触发"的**已确认现象**，整套算术都建在它上面 —— 而那是**推断**。⚠️ 推不出语义的表象（一颗灯、一个 `0.0°`）**只能当假设，不能当证据**；要让它变证据，必须先设计一个**能把假设证伪**的实验（如关掉保护看灯还亮不亮）。
- **不能只看"通过"**：`0 Error(s), 0 Warning(s)` **完全不能证明代码进了镜像** —— 判据要看 `AVE.map` 里的 **`Removing`** 行（无调用者时 armlink 会把整节删掉）。
- **计数器判不出时序**：加锁 1 次 / 放锁 1 次 / 延时 1 次，三个数全正常，而延时可能正好在锁里面 ⇒ 新写了 `host/host_trace.{h,c}` 按**发生顺序**记事件，判据形如 `trace_delay_in(lock, unlock) == 0` 且 `gap > unlock`。错法（M24a）的现象：把 10 ms 帧间隔挪进锁内 ⇒ 等锁的高优先级任务白等 10 ms，**正好是 50 Hz 控制环的一拍**，而线上波形与计数器**全都正常**。
- **观测量的语义必须追到赋值链，不能按名字猜**（T2 那次）。
- **"全部通过"不是证据，必须做变异测试**；且要分清"变异没生效"与"用例太弱"。
- **负向测试的判据必须落在被测物上**，不能落在"我期望的报错格式"上（M1.2 那次的假 FAIL：脚本找展开后的 `chk_off_is_low`，而 armcc 回显的是宏调用原文 `CHK(off_is_low, ...)`）。
- **判据的出处比被测对象还硬的时候，错的是判据**（手册示例 `0F A0` = 4000 超出文档写的 0~0x4FF ⇒ 删掉那道上限）。
- **靠人记的清理迟早会漏** ⇒ 一律做成**编译期开关**（默认 0 的诊断宏），如 `AVE_DIAG_BLOCK_VISION_MS`、`AVE_DIAG_JOG_PULSES`。漏掉的后果：一个"开机自动动"的固件留在机器上、或视觉任务永远 5 秒一轮（**看着像性能问题**）。

### 5.2 拓扑与接线（关键结论）

- **电机是"一体机"**：本体 + 驱动器 + 编码器封在一起，引出 `V+`/`GND`（电源）与 `PUL`/`DIR`/`ENA`（指令，实物丝印 **`Stp`/`Dir`/`En`**）+ **串口**（`Gnd`/`Tx`/`Rx`），**没有相线端子**。
- ⇒ 🔴 **`D36A` 的 `A+`/`A-`/`B+`/`B-` 相线输出在这套里无处可接** ⇒ **`D36A` 在本工程只剩"电源分配板"一个角色**（12V 进 → 并联输出 → 电机 `V+`/`GND`）。
- 🔴 **连带作废**：`D36A` 的细分/电流拨码**对这套不起作用**（它内部两个 ATD5984 没接任何电机）。用户报的 `on/off/on/off/on/off` ＝ 1/32 细分、0.93 A（据 `D36A` 手册表 2-2/2-3 算得）**在本拓扑下不成立**。⇒ **真正的驱动器是电机侧的张大头 `Emm42_V4.2`**，控制端子为 **`V+` / `Gnd` / `Com` / `En` / `Stp` / `Dir`**（**单个 `Com`**，**不是**差分 `PUL±`/`DIR±`）。🔴 **它的细分设置我查不到，是 §1.3 的问题 1。**
- **接线（第二十/二十一次核对，与引脚定案逐条一致）**：`D36A Vout+` → 两电机 `V+`（12V 功率）；`D36A Vout-` → 两电机 `GND` **且 → `STM32 GND`**（**共地**）；`D36A 5V` → 两电机 `Com`（**用户 2026-09-29 报已接**，建议**星形**分两路、别菊花链）；MCU 的 `Stp`/`Dir` → 电机侧 `Stp`/`Dir`。
- 🔴 **`Com` 不接 ⇒ 三路光耦都没有回路 ⇒ 一根脉冲都不会动**（`Com` 是 `En`/`Stp`/`Dir` 的公共端）。

### 5.3 极性与电平

**极性由"用户选的接线"决定，不必等手册**（这是关键简化）：`Com` → 正极（**共阳**）⇒ MCU **拉低导通** ⇒ **低有效** ⇒ CubeMX `Polarity = Low`（**空闲高、脉冲低**）；`Com` → `Gnd`（共阴）⇒ 高有效 ⇒ `Polarity = High`。**两者一致就一定能动；不一致则方向反/不动作。**
✅ 实测生成物：`TIM2_CH3` / `TIM5_CH4` 的 `Polarity = Low` 落在 `Core/Src/tim.c:72`、`:126`（第二十五次核对）。
**极性错的现象（别再概括成"完全不转"）**：`Stp` 反 ⇒ **仍然转**，只是步进时刻移到另一个边沿（**脉冲数不变 ⇒ 转角不变**）；`Dir` 反 ⇒ **方向反**（主要症状，改软件符号位一行即可）；空闲电平落在"有效"侧 ⇒ 光耦 LED **常亮**（约 5~10 mA/路，不影响功能、白耗电、抗干扰差）。**三者都不报错，别从报错文本猜。**

### 5.4 供电拓扑

- **`STM32` 没有独立供电口**，**`ST-Link` 的 3.3V 也没接** —— 是**靠 `D36A` 的 3.3V** 供电（用户原话「靠的 `d36a` 的 `3.3v*2`」）。
  ⇒ ✅ **此前担心的「12V 进 `3.3V` 轨烧板」不成立，板子大概率没被烧。** 但换来三条固有风险，见 §4.1 的 #10 #11。
- ⚠️ `D36A` 的 `5V` 输出**别与 USB 同时接**（两个 5V 源顶牛）。
- **电源 12V 至此裁决**（`D36A` 手册 §3.1：`Vin±` 外接 12V，12V 有并联输出可级联）。

### 5.5 定时器参数（`PSC` 必须分频）

`TIM2`/`TIM5` 挂 `APB1` = **84 MHz**；`PSC=99` ⇒ **840 kHz** 时基、`ARR = 840000/f`。
**最低速 = 840000/65535/8.889 = 1.44 °/s**；5 °/s → `ARR=18919`；57 °/s → `ARR=1657`（分辨 0.03 °/s）。
✅ 上板实测 `[TIM] tb=840000 clk=84000000 exppsc=99 A=99,0068,0300 B=99,6800,3000 bad=0,0`（`A`/`B` 三字段依次是 `PSC`,`CCMR2`,`CCER`；`0068` = PWM 模式 1 + `OCxPE`）。
🟢 **官方例程（`D36A` 手册 §3.2）就是用定时器 PWM 驱动 `ST`：`TIM8` 的 CH3/CH4 出两路脉冲** —— 厂家已验过这条路。

⚠️ **"跟 STM32 没关系"只在"没有导线相连"这一层成立，电气上不成立**：

1. 两端子同一颗 LDO ⇒ 光耦负载仍加在**给 STM32 供电的同一颗芯片输出**上；
2. **回流路径绕不开 STM32**：共阳接法下电流走
   `D36A 3V3 → 光耦 LED → Stp/Dir 线 → STM32 引脚(灌电流) → STM32 内部低边 → STM32 GND → D36A GND`。
   这股电流**必然**从 STM32 的 IO 与地线上过 —— 这是共阳接法的属性，**不是接线选择**。

⬜ `D36A` 手册**未给 3.3V LDO 的电流额定值**（grep `输出电流|1117|LDO` 无果）⇒
多背 2 组光耦（`Stp`+`Dir` × 2 轴 ≈ 4 路）够不够，**文档答不了，只能实测**。

**回填 §5.6.2 判别实验的第二步**：若 `3V3` 下 OLED 记 **+0**，把 `Com` 临时挪回 **`5V`** 再发 20 做对照 ——
`5V` 下 +20 / `3V3` 下 +0 ⇒ **3.3V 下光耦电流不足** ⇒ 走**方案 C**（`5V` + 开漏）；两边都 +0 ⇒ 不是 `Com` 电平的事，转查接线 / 极性 / `Mode` 菜单。

### 5.7 `clk≡0` / 飞车 排查全史（第三十五~六十五次，**已结案**；逐轮过程见 `verify.md`）

> **压缩说明（2026-10-21）**：原 559 行逐轮叙事压成「结论 + 撤回留痕」。**失败记录、⬜、🔴 一条未删**；过程细节去 `verify.md` 对应轮次查。

#### 5.7.A 最终结论（2026-09-30 定案）

1. **`clk≡0` 根因两条**：① 水平轴 `Stp`/`Dir` **插错排针**（用户自己找到）；② 俯仰轴**从未被命令过**（固件每次复位只点动一个轴）。**与驱动器硬件、与 STM32 代码都无关。**
2. **两轴脉冲链全通**：改正接线后，水平 `PB10`/`TIM2_CH3` 每复位 `clk +20`；`AVE_DIAG_JOG_AXIS` 0→1 后俯仰 `PA3`/`TIM5_CH4` 每复位 `+20`。`20` 恰等于 `AVE_DIAG_JOG_PULSES` ⇒ **引脚上真的翻转了 20 次**。
3. **细分定案 = 16** ⇒ 3200 脉冲/圈 ⇒ `8.889f` 步/度，**代码不动**。
4. **竖直「疯转」其实是两种现象**：① 上电自己跑 = `O_POT_En=enable` 的上电回零（已关，消失）；② 静止没事、一碰就飞 = **闭环正反馈**（带载 `Cal` 不成立）。
5. **飞车修复** = 拆电机、平放、**空载**重按 `Cal`（顺/逆各转一圈），装回 `foc` ⇒ 轻碰不飞。

## 七、FreeRTOS 资源约束（写任务时必须遵守）

```
configTOTAL_HEAP_SIZE                          = 32768 字节   ✅ 已改（原 15360）
configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY   = 5
configMAX_PRIORITIES                           = 56
configTICK_RATE_HZ                             = 1000
configCHECK_FOR_STACK_OVERFLOW                 = 2
configMINIMAL_STACK_SIZE                       = 128
```

| 任务 | 栈（字节） | 优先级 | 周期（ms） |
| --- | --- | --- | --- |
| `VisionTask` | 1024 | 高 | 20 |
| `MotorTask` | 768 | 中高 | 10 |
| `CmdTask` | 1024 | 中 | 10 |
| `HeartbeatTask` | 🔴 **512** | 低 | 2000 |

合计 3328 字节 + TCB。`osThreadNew` 堆不足时**静默返回 NULL** ⇒ **必须逐个检查返回值**（已实现，且有变异测试守着）。
- ✅ **心跳任务 512 字节已上板排除**（`ovf=0`）—— `AVE_Log()` 每次在**调用者栈上**开一个 `AVE_LOG_LINE_MAX`(=100) 的缓冲，再加 `vsnprintf` 的开销；编译期约束 `AVE_TASK_HEARTBEAT_STACK > AVE_LOG_LINE_MAX` 管不了 `vsnprintf` ⇒ 只能实测，**实测过了**。⚠️ **将来日志行变长（如打印 JSON）要重新看 `ovf=`。**
- CMSIS-RTOS2 的 `osThreadAttr_t.stack_size` 单位是**字节**，不是字。
- 串口环形缓冲（1024 × 3）与发送缓冲 `s_tx_buf` 都**用静态数组**，不从堆上分配（"先拷后发"）。
- 中断优先级**数值必须 ≥ 5** 才能调用 `FromISR` 系列接口。
- 🔴 **内核对象必须在 `osKernelInitialize()` 之后创建**：在它之前创建，编译链接全过、上电不报错、**任务一个都不跑**（没有任何运行时症状，只有"什么都没发生"）。
- 🔴 **两个入口**：`AVE_App_Init()`（纯外设，`main.c` 的 `USER CODE 2`，**在 `osKernelInitialize()` 之前**）／`AVE_App_RtosInit()`（互斥量 + 四个任务，`freertos.c` 的 `USER CODE BEGIN RTOS_THREADS`，返回 `-1` 时进 `Error_Handler()`）。
  ⚠️ **不要在调度器启动前指望任何输出** —— 那时 `AVE_Log()` 是**静默无效**的（字节进不了线）；失败原因改存 `AVE_App_FailName`，在调试器 Watches 里看。
- **`AVE_App_Init()` 内的固定顺序（不能变）**：安全 → 串口 → 视觉 → 电机，四步全在 `osKernelStart()` 之前。
- **`AVE_App_RtosInit()` 里锁的顺序不能反**：`AVE_Gimbal_SetBusMutex(s_motor_mutex)` 要**先于**任何发送接口存在。
